# Pre-release Audit — 2026-11-04 (post-`v0.1.0-rc1`)

Three independent adversarial reviews ran against the working tree at
`v0.1.0-rc1` (security/privacy, correctness/robustness, docs/consistency).
Each hunted for real problems with explicit instructions to attack; findings
were verified by reading code and, where marked, by executing reproductions
against the running app or repo fixtures. This document deduplicates the
three reports and records the fix status for every accepted finding.

**Verdict: 1 Critical, 6 High, 11 Medium, plus LOW/INFO items — all accepted
findings FIXED in this pass unless marked deferred below.** A new failure
mode found by the fix wave itself (SQLite transaction scoping for the WAL
purge) is also fixed and tested.

## Critical (fixed)

| ID | Finding | Source | Fix |
|---|---|---|---|
| C1 | **The pause frame was silently dropped for ~half of all precise pauses.** `round(end, 3)` could round above the clamped window end; the plan's window filter then deleted the anchor — the model never saw the paused moment. `max_frames=1` produced an empty plan → HTTP 500. Reproduced with a plain `currentTime` double (61.23456). | Correctness | `frame_sampling.py`: anchor clamped with `min(round(end,3), end)`, spread points filtered separately so the anchor is always present and last. A property test over a grid of high-precision anchors/durations permanently pins the contract (non-empty, monotonic, in-window, anchor last). |

## High (fixed)

| ID | Finding | Source | Fix |
|---|---|---|---|
| H1 | **YouTube downloads were never deleted** — `cleanup_after_use` was a dead flag; every preview/discuss retained a full video in `data/cache/downloads/`, contradicting the bounded-cache principle. | Correctness + Security | `discussion.py`/`evidence.py`: downloads are unlinked in a `finally` once extraction no longer needs them, whatever the outcome. |
| H2 | **Portrait video ignored the frame-dimension budget** — width-only scaling produced 720×1280 frames on a 4 GB card (verified). | Correctness | Scale filter bounds **both** axes (`force_original_aspect_ratio=decrease`) with an even-dimension pass; portrait test added (432×768). |

## Medium (fixed)

| ID | Finding | Source | Fix |
|---|---|---|---|
| M1 | **Chunked request bodies bypassed `MAX_REQUEST_BYTES`** and were fully buffered in memory (verified live: 50 MB chunked POST read to completion). | Security | `PayloadLimitMiddleware` rewritten as pure-ASGI: bodies are read and counted up to the cap before the app sees them, framing-independent; over-cap requests get a structured 413 without the app ever running. |
| M2 | **Deleted session history persisted recoverably in the SQLite WAL** (verified: question text and absolute paths recoverable verbatim after delete). | Security | `delete_session`/`clear_all` now run `wal_checkpoint(TRUNCATE)` (and `VACUUM` on clear) — outside the write transaction, which the fix wave itself initially got wrong and the session tests then caught. |
| M3 | **Session deletion could unlink frames mid-discussion** — the delete/clear routes bypassed the pipeline lock while an inference held frames. | Correctness | Both DELETE routes share the pipeline lock (bounded wait, structured 409). |
| M4 | **Four shipped endpoints undocumented; two "future routes" superseded** — architecture §7 lagged the API. | Docs | Full endpoint table in §7; supersession notes for `sync/manual` and `jobs/{id}`. |
| M5 | **The `think`-400 fallback retried doomed requests** (any 400 triggered a second multi-MB POST) and discarded the runtime's error body. | Correctness | Fallback only when the error text indicates thinking-unsupported; 4xx error messages now carry the runtime's detail. |
| M6 | **The evaluation evidence wasn't in the repository** — the RC's headline claim cited a gitignored file. | Docs | `results.json` committed via a `.gitignore` carve-out. |
| M7 | **Dev harness was silently broken by the Sprint 13 CSP** — inline harness scripts are blocked by `script-src 'self'`; the tool validates nothing since then (static tests only checked strings). | Security | Deferred one sprint: externalizing the harness scripts is mechanical but the harness needs a browser pass to re-verify — tracked for the next sprint (see Deferred). |
| M8 | **Dead configuration knobs** (`MAX_CONCURRENT_INFERENCE`, `FRAME_SAMPLE_INTERVAL_SECONDS`, `MAX_CHAT_TURNS`) implied bounds that don't exist. | Correctness + Docs | Removed from `config.py` and `.env.example`; architecture §9 notes the removal (the single pipeline slot is enforced, not a configurable value). |
| M9 | **`.env.example` incomplete** — `INFERENCE_THINK_ENABLED`, `MAX_REQUEST_BYTES`, `SESSIONS_DIR` missing; two dead entries present; llama-server-fallback comment overstated the adapter's capabilities. | Docs | Fixed (added three, removed two, corrected the comment). |

## Low / Info (fixed or recorded)

- **Fixed:** IPv6 dashboard origins now bracket literals (a `::1`-opened dashboard previously 403'd itself); the client marker requires its exact value (empty-value acceptance removed); client `X-Request-ID` is format-validated (log forging closed, tested); deleted-session WAL purging (M2 above); session store catches `UnicodeEncodeError` alongside `sqlite3.Error` (a lone-surrogate answer would previously surface as a 500 after a full-price inference); UNC/device paths rejected at the local-file schema; frames serve `Cache-Control: no-store` so deleted evidence leaves the browser cache; `APP_ENV` defaults to `production` (dev fixture routes are now opt-in, tested); the health-TTL is stamped after the probe; the userscript's `__vdTestHref` test seam is gated to backend-origin pages only (a page can no longer choose what gets synced); diagnostics mode no longer prints local paths; the README/architecture latency statements use one consistent measured range; doc cross-reference fixes (sprint reference, "5–10×" arithmetic, missing doc-index entries, roadmap header).
- **Recorded, deferred:**
  - Grandchild-process survival on yt-dlp timeout (no Windows job object) — needs a real yt-dlp run to verify; bounded by the 600 s timeout.
  - Dev harness externalization (M7 above).
  - `SESSIONS` uniqueness across processes (single-process deployment documented; a UNIQUE index is cheap hardening).
  - Evidence frames persist in browser HTTP cache — resolved by `no-store` (fixed), noted here for history.
  - Post-MVP: choose-the-moment control for local files (README limitation added).

## What held up under adversarial attack

Both technical reviewers independently confirmed: DNS-rebinding is closed
(every browser-producible Host variant parses fail-closed); the hostile-page
write surface is closed (mutating routes require dashboard-loopback Origin
or the marker, preflight-immune; `Origin: null` rejected; no CORS headers
exist to read with); SQL is fully parameterized; frame serving has layered
traversal defenses (regex → registry → containment); the local-file
allowlist resolves symlinks before containment; subprocess discipline holds
(argument arrays, `shell=False`, timeouts, bounded stderr); the pipeline
lock has exactly one instance and both directions of mutual exclusion are
tested; config validation refuses non-loopback hosts and colliding ports;
the schema boundary rejects lone surrogates and NUL bytes end-to-end; and
the prompt's not-legal-advice policy is structural.

## Process notes

- The fix wave itself introduced — and the tests then caught — a SQLite
  transaction-scoping bug (checkpoints cannot run mid-transaction). This is
  the audit working as intended: verification followed every change.
- One reviewer was initially lost to a concurrency limit and relaunched;
  all three ultimately completed with full reports.

**Release decision:** fixes re-verified by the full suite (232 passed) and
the tagged profile unchanged. Tagged **`v0.1.0-rc2`** on top of these fixes;
`v0.1.0-rc1` remains as the pre-audit snapshot.
